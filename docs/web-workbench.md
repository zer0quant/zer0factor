# Web 工作台

浏览器界面，共五个页面：

| 页面 | 内容 |
|---|---|
| **因子看板** `/` | 一行一个原始因子，只看主版本的方向和各项指标 |
| **因子主页** `/base/<原始因子>` | 版本表格、叠加曲线，以及选中版本的详情 |
| **因子对比** | 指标并排、多头曲线叠加（可切换多头超额）、截面相关性热力图 |
| **因子族** | 自动发现的因子族；可以构建，然后接着评估 |
| **任务** | 后台任务的进度、日志，支持取消和重跑 |

## 启动

```bash
# 首次使用：构建前端（需要 Node 18+）
cd web && npm install && npm run build && cd ..

# 启动（默认只监听 127.0.0.1:8600）
uv run python main.py serve

# 服务在远程服务器上时，在本机做端口转发，然后打开 http://localhost:8600
ssh -L 8600:localhost:8600 <服务器>

# 可选：为一次评估的全部因子预先生成图表缓存（不预热的话，首次打开单个因子要 1–2 分钟）
uv run python main.py web-warm --run <run_id> --workers 12
```

新的评估写进 `data/evaluations/` 以后，刷新页面（或调用 `POST /api/refresh`）就能看到。

**安全**：工作台没有鉴权，任何能访问服务地址的人都能发起任务。只在可信网络里绑定非本机地址。

**前端开发**：先启动 `serve`，再在 `web/` 下运行 `npm run dev`。Vite 会把 `/api` 代理到 8600 端口。

## 统一评估口径

看板、因子主页的数字都来自**统一口径**的最新一次评估。统一口径的定义在 `config/settings.toml` 的 `[web.standard]`：区间起点、分位数、持有期、成交价、股票池都要一致，并且要评估到最新。

“评估到最新”指结束日留空，或者结束日不早于目前所有评估达到的最新数据日。

页面上的股票池和成交价显示中文名，例如 `univ_trade_base` 显示为“基础交易池”，`open_t1` 显示为“次日开盘成交”。悬停股票池旁的问号，可以查看过滤规则。

## 因子看板

因子名拆成三部分：原始因子 × 处理方式（原始 / Z / 市值中性 / 行业中性 / 行业+市值中性）× 周期（`_maN`）。

看板一行一个原始因子，只看**主版本**：

- 主版本由 `[web.board] primary_prep` 指定，默认是行业+市值中性。
- 市值类因子做不了市值中性，改用 `industry_only_prep`，默认是行业中性。

各列的含义：

- **方向**：主版本各窗口的评估方向一致时，显示“正向”（因子值越大，未来收益越高，红色）或“反向”（绿色），不一致时显示“方向不一致”。
- **ICIR（窗口中位数）**：主版本各窗口方向调整后 ICIR 的中位数，用来衡量逻辑整体是否有效，而不是挑出最好的窗口。悬停可以查看各窗口的值。
- **其他指标**：方向调整 IC、t 值、IC 胜率、多头年化 / 回撤 / 夏普 / 超额、单调性、多头换手，同样取主版本各窗口的中位数。“列设置”可以隐藏或显示列。

有三种原始因子不在看板表格里列出，也不给数字、不拿其他版本顶替：主版本还没评估的（“待评估”）、存储里没有主版本的（“待中性化”）、方向不一致的。它们收在标题旁的“另有 N 个待处理”里，点开可以进入它们的主页。

## 因子主页

### 版本表格

行是处理方式，列是周期，最后一列是中位数。行分三组：

- **主版本**：行业+市值中性。
- **对照**：“原始（Z）”。Z 分数在评估股票池内和原始值的截面排序完全一致，所以只保留这一行。
- **归因**：市值中性、行业中性等，默认折叠。只用来拆解效果的来源，不用来挑版本。

可以切换显示 ICIR、多头超额、多头年化、单调性、IC 胜率。格子里的标记：

- “未评估”：还没有评估。
- “无数字”：已经评估，但这个指标是空的。
- “—”：没有这个版本。

表格不用色阶，因为要看的是各版本是否一致，而不是挑最好的一格。

操作：点格子切换版本，浏览器后退能回到上一个版本；`h` / `l` 切换周期，`j` / `k` 切换处理方式。

### 叠加曲线

把同一处理方式下的各周期（或同一周期下的各处理方式）画在一张图上，默认画多头超额，也可以切换成多头累计收益。只读取已有的图表缓存。

### 版本详情

只显示这个版本最新一次统一口径评估的结果，和看板、表格、曲线用的是同一次。不能切换到旧的评估或非统一口径的评估；没有统一口径评估的版本，详情为空。

从上到下依次是：

1. 5 个核心数字：ICIR、方向调整 IC、多头年化、多头超额、单调性。
2. 分组累计收益（只画各组，未扣费）和分层收益柱状图（每组的超额年化 / 年化收益），两张图并排。
3. IC 分析：只看 Rank IC，有序列与累计、衰减两张图。
4. 更多指标。
5. 分组收益明细。
6. 最新因子值。

以上内容全部直接展开。这里还可以重新评估此版本、一次评估主版本全部未评估的窗口、把此版本加入对比。

旧链接 `/factor/<因子名>` 会跳转到对应的主页和版本，链接里的 `run` 参数会被忽略。

## 后台任务

在网页上发起的评估、构建、基础因子计算、缓存预热，都是后台任务：

- 任务以独立进程运行，重启 `serve` 不会中断任务。
- 任务记录和日志保存在 `[web] state_dir`，默认是 `data/workbench/`。
- 评估和构建同时最多跑 `[web.tasks] heavy_slots` 个（默认 1 个），其余排队。
- 评估成功后，会自动预热缓存并刷新看板。
- 在命令行直接运行的任务不显示在任务页里，也不计入并发上限。

新建评估有三个入口：看板对比篮里的“评估”、详情页的“重新评估”、因子族页的“接着评估”。打开“统一口径”开关后，评估结果会进入看板。

## 因子族自动发现

- 配置 `[families] packages = ["zer0alpha.factors"]` 后，会扫描这些包下导出了 `FAMILY` 的子模块，`_` 开头的模块跳过，不需要逐个登记。
- `[external_families]` 仍然可以用。
- 加载失败的族，在因子族页上标红并显示报错。
- 模块里可以声明 `SOURCE = {"paper": ..., "url": ..., "formula": ...}`，记录因子来源。
- 扫描和任务用 `[web.tasks] python` 指定的解释器执行，默认是服务自身的解释器。要构建 zer0alpha 的因子族，需要把它指向 zer0alpha 的 venv。

## 缓存与界面

- 详情页需要的日度序列会派生到 `data/web_cache/`，可以随时删除，之后会重建。新的评估会直接写出这些序列。
- 右上角按钮切换浅色 / 深色，选择保存在浏览器本地。切回和系统一致的配色时，会恢复跟随系统。
- 窄屏（手机）下，侧边栏收进左上角的菜单。
- 详情页的累计收益图可以切换对数坐标。
- 对比页热力图的横轴用 `#1`、`#2` 编号，对应纵轴上的因子名。
