# 因子主页：版本总览 + 简化详情 设计

日期：2026-11-08
状态：待确认
前置：`2026-11-08-board-by-base-design.md`（方案 D，提交 1dbdb4b）

## 1. 目的

研究员不会一个个点开 30 个版本（处理方式 × 周期），而是**对比着看**：效果在不同处理方式、不同周期下是否一致（稳健性），而不是挑出最好的一格。同时现在的单版本详情信息太多，要一屏回答“这个版本有没有用”。另外修掉“主页默认用旧 run”的问题。

## 2. 目标 / 非目标 / 反目标

- 目标：
  - 主页顶部放版本表格，表格下面是叠加曲线，选中版本的详情按方案 A 简化。
  - 主页和看板默认使用最新的统一口径评估。
- 非目标：改 `zer0factor/eval/` 的指标；鉴权；看板（`/`）的布局。
- 反目标：
  - 表格用色阶，或者标出“最好的一格”，诱导挑最好的版本。
  - 表格、曲线、详情用的不是同一次评估。

## 3. 方案取舍

| 方案 | 做法 | 结论 |
|---|---|---|
| **1. 后端专用接口** | `/api/bases/{base}` 带上各版本指标；新增 `/api/bases/{base}/curves` 只读缓存 | **用户选定** |
| 2. 前端逐个请求详情 | 每个版本调用一次详情接口 | 不选：约 30 个版本，数据量达几十 MB；没缓存的版本还要重新计算 |
| 3. 复用 `/api/compare` | 用对比接口画叠加曲线 | 不选：只有多空曲线，挑 run 的规则也和主页不同 |

布局取舍：用户选了 A（核心数字一行，两张图并排），不选 B（指标放在侧栏）。总览选了 X（版本表格加曲线叠加），不选 Y（小图网格）。

## 4. 默认 run 的修正（`zer0factor/web/runs.py`）

- 现状：`is_standard` 要求 `end_date is None`。`20261107_205716` 写了结束日 `20260515`，所以被排除，129 个因子都退回 `20260614_135227`。两次评估的实际数据都截止到 20260515。
- 新规则：结束日留空，**或者结束日不早于“最新数据日”**，都算“评估到最新”。最新数据日取所有带 summary 的 run 中 summary 里 `end_date` 的最大值。其他条件不变。
- 影响：看板、主页、对比页都会改用 11-07 这次评估，因为它们共用 `standard_rows` 和 `is_standard`。run 下拉框里它也会标“标准”。

## 5. 接口

- `GET /api/bases/{base}`：每个版本额外带上 `metrics`，键和看板一致（`ic_adj, icir, t_stat, ic_win_rate, long_ann_ret, long_max_dd, long_sharpe, long_exc_ann_ret, monotonicity, turnover_long`）。
- `GET /api/bases/{base}/curves?prep=<p>` 或 `?win=<N|none>`，加上 `&kind=long_excess|ls`：
  - 返回 `{dates, series: {版本名: [累计值]}, missing: [版本名]}`。
  - 带 `prep` 时取该处理方式的各周期，带 `win` 时取该周期的各处理方式。
  - 每个版本用最新一次统一口径评估，持有期按统一口径。
  - 只读缓存，不重新计算。没有缓存或没有评估的版本放进 `missing`。
  - 多头超额 = 多头组合每日收益 − 基准每日收益，再求累计收益（与分组表的“超额年化”同一口径）。

## 6. 前端 `/base/:base`

1. **头部**：中文名、base、方向、主版本 ICIR 中位数，和现在一样。
2. **版本表格**（取代处理方式标签页和周期按钮）：
   - 行是处理方式，主版本那一行高亮并加“主版本”角标。
   - 列是周期，最后一列是“中位数”，即该处理方式下有数字的各窗口的中位数。
   - 表头可切换显示的指标：ICIR（默认）、多头超额、多头年化、单调性、IC 胜率。
   - 格子文字：数字 /“未评估”/“无数字”（已评估但该指标为空）/“—”（没有这个版本）。
   - 不用色阶。当前版本的格子加边框；点击格子切换版本，切换写进浏览器历史，可以后退。
   - 保留 `h` / `l` 切换周期，新增 `j` / `k` 切换处理方式。
3. **叠加曲线**：
   - 切换“同处理方式比周期”（默认）和“同周期比处理方式”；切换“多头超额”（默认）和“多空”。
   - 当前版本的线加粗，悬停显示各线的数值。
   - 有缺失的版本时，在图下方用小字列出。
4. **选中版本详情**（方案 A）：
   - 评估信息一行：run 下拉框、持有期、参数摘要、重新评估、加入对比。
   - 5 个核心数字排成一行：ICIR（方向调整）、方向调整 IC、多头年化、多头超额、单调性。
   - 两张图并排，窄屏时上下排：分组累计收益（第 1 组绿 → 第 10 组红），以及分层收益柱状图。
   - 分层收益柱状图默认显示每组的年化超额，可以切换成年化收益（**我的决定**：你还没选，超额更能看出单调性）。
   - 其余内容默认折叠：更多指标（原核心指标区的其余数字）、分组收益明细表、IC 分析、最新因子值。
5. “评估全部未评估窗口”留在版本表格上方，把“无数字”的版本也算进去（处理遗留问题 3）。

## 7. 留给实施时决定

- 叠加曲线默认画到最新日期，不做抽样；10 年日度数据每条约 2500 个点，6 条线没有压力。
- 窄屏时版本表格可以横向滚动，处理方式那一列固定在左侧。
- 验证：
  - pytest 覆盖新的标准判断、版本 `metrics`、curves 接口的两种模式和 `missing`。
  - `npm run build`。
  - 在单独端口的验证服务上截图，至少包括 `daily_return`、`intraday_rtn_var_up`、`log_total_market_cap` 三个主页，以及窄屏。

## 8. 追加：精简版本表格（2026-11-08）

**为什么**：中性化应当事先定好，不能拿来调参数（Grinold & Kahn 第 14 章；券商单因子测试的流程是固定的）。处理方式越多，挑出最好一格的机会越多，过拟合风险越大（Harvey-Liu-Zhu；Menkveld 等的 Non-Standard Errors）。我在本地验证过：在评估股票池内，Z 版本和原始版本每天的截面排序完全一致（35 对因子，各抽 40 个交易日，排序相关全部是 1.0000），所以 Rank IC 和分组收益两者基本相同。

**规则（纯前端，后端接口不变）**：

- 表格的行分成三组，从上到下：
  1. **主版本**：`primary_prep`。
  2. **对照**：存在 `z` 时显示 `z` 这一行，标为“原始（Z）”，并隐藏 `raw` 行；没有 `z` 时用 `raw`，标为“原始”。
  3. **归因**：其余处理方式（市值中性、行业中性、旧的 `z_neu`、Rank 系列）。默认折叠，表格下方有“展开归因（N）”的切换。
- 当前版本落在归因组，或落在被隐藏的 `raw` 上（例如通过链接或 `j`/`k` 进入）时，自动展开归因组或显示该行，不会出现选中了却看不见的情况。
- `j` / `k` 只在可见的行之间移动。
- “评估全部未评估窗口”只针对主版本：只要主版本里有“未评估或无数字”的窗口就显示按钮，与当前选中哪个版本无关。
- 叠加曲线“同周期比处理方式”只画可见的行。

**我的决定**：
- “展开归因”的状态记在 URL 参数 `attr=1` 里，刷新后保持。
- 主版本行加浅色底（审查时提出的小问题 4）。
- 主版本不存在时（待中性化），对照行排在最上面，主版本行显示为“—”占位，并标出“主版本（待中性化）”。

## 9. 追加：配色切换简化为单个图标按钮（2026-11-08）

**为什么**：右上角“自动 / 浅色 / 深色”三段切换占地方、看着复杂；常见网站只放一个图标。

**方案取舍**：A 单个图标按钮点击切换（**用户选定**）；B 图标 + 下拉三选项（GitHub、Tailwind 文档的做法，多一步点击，不选）。

**规则**：
- 一个无边框小按钮，内联 SVG 图标（不新增依赖）：当前浅色显示月亮，当前深色显示太阳；悬停提示“切换到深色 / 浅色”。
- 首次打开仍跟随系统（不写 localStorage）。点击切到相反配色；若切换后的配色与系统一致，则清除存储、回到“跟随系统”，否则记住选择。
- 系统配色变化时：跟随系统状态下自动跟随；已记住选择时不跟随。
- 位置不变（宽屏侧栏、窄屏顶栏原位置）；`ThemeMode` 类型和存储键不变，旧存储值继续有效。

## 10. 追加：叠加曲线改为“多头超额 / 多头”（2026-11-08）

**为什么**：用户只关心多头，多空不需要；但应能看多头自身的累计收益（绝对收益、回撤）。

**规则**：
- 叠加曲线的切换改为“多头超额”（默认）和“多头”，去掉“多空”。
- 默认多头超额（用户认可的建议）：图用来比较版本，绝对收益里大盘涨跌是各版本共有的，会掩盖差异；且与表格、看板的“多头超额”同口径。
- “多头” = 多头组合每日收益的累计（不减基准），持有期按统一口径。**扣费后**：多头 / 多头超额曲线都来自 `portfolio_daily_returns`（与核心数字同一套扣费后组合构建），而分组累计收益里的各组线是未扣费的等权收益。（更正：初稿误写为“未扣费、与分组累计收益图同口径”。）
- 后端 `/api/bases/{base}/curves` 的 `kind` 新增 `long`；`ls` 仍保留在接口里（**我的决定**：改动最小），界面不再提供。URL 参数 `kind=long` 表示多头；旧链接 `kind=ls` 落回默认。

## 11. 追加：分组累计收益图只画 10 组（2026-11-09）

**为什么**：图里的“多头 / 空头 / 多空”三条线与分组线重复（多头≈多头那一组的扣费版），空头在 A 股基本不可做，多空用户不需要；而且这三条是扣费后、各组是未扣费，同一张图混了两种口径。

**方案取舍**：A 保留“多头（扣费后）”去掉空头和多空（不选）；B 只留 10 组（**用户选定**）：口径统一为未扣费，扣费影响看分层收益图下方的“成本拖累”。

**规则**：`CumulativeChart` 只画 `groups`，去掉“空头默认隐藏”的提示；后端 `cumulative` 里的 `long/short/ls` 保留不动（**我的决定**：接口不变）；后端 `notes` 去掉“多头/空头/多空为扣费后组合收益”那条，只留“分组曲线为各组等权毛收益（未扣费）”；卡片标题加“未扣费”小字。

## 12. 追加：详情不再折叠（2026-11-09）

**为什么**：图表精简后详情不长了，折叠反而要多点几下。

**规则**（用户定：全部默认展开）：去掉折叠面板，改为依次排列的卡片——核心数字 → 分组累计收益 + 分层收益 → IC 分析（Rank IC 序列与累计 + 衰减并排，“按方向调整”开关放在序列卡片右上角）→ 更多指标 → 分组收益明细表 → 最新因子值。最新因子值随页面一起请求（原来是展开时才请求）。

## 13. 追加：两处小修（2026-11-09）

- “IC 衰减按每 N 个交易日抽样计算”的说明从分组累计收益图下移到 IC 衰减图下（前端按 `notes` 前缀“IC 衰减”分流）。
- 最新因子值让多头组排在前面：反向因子按因子值从低到高排。`/api/factors/{name}/runs/{run_id}/latest` 新增 `ascending=true`（缓存仍按从高到低存，取时反转）；表头文字写明排序方向。

## 14. 追加：无窗口列按需显示（2026-11-09）

**为什么**：现有因子的主版本都没有无窗口版本，对照行的无窗口版本都未评估，这一列整列是“—/未评估”，没有信息。但有的因子只有无窗口版本，不能一刀切删掉。

**规则**（用户认可）：
- 可见行里，只要有一个无窗口版本“已评估且 ICIR 有数字”，就显示该列；否则隐藏。判断用 ICIR 而非当前所选指标，切换指标时列不会忽隐忽现（**我的决定**）。
- 当前选中的是无窗口版本时（链接或 `h` 进入），该列照常显示。
- 叠加曲线“同处理方式比周期”下方的“无曲线”提示，在该列隐藏时不再列出“无窗口”。
- 中位数原本就只算有数字的格子，不受影响。
