# 看板按原始因子组织（方案 D）设计

日期：2026-11-08
状态：待确认

## 1. 目的

因子名 = 原始因子（base）× 处理方式（prep）× 周期（`_maN`）。现在看板把 200 个版本平铺，处理方式和因子平级显示，研究时容易在几十个版本里挑最好的，造成过拟合。

改成：**看板只列原始因子，看“这个因子的逻辑整体有没有用”；所有版本收进因子主页。**

## 2. 目标 / 非目标 / 反目标

- 目标：看板一行一个原始因子，只显示名称、方向、一个数字；因子主页用“处理方式标签页 + 周期按钮”切换版本，下方是现有详情内容。
- 非目标：研究逻辑的一句话描述（用户决定不要）；改 `zer0factor/eval/` 的指标；鉴权。
- 反目标：看板上的数字是从多个窗口里挑出来的最好值；没有主版本的因子拿别的版本顶替数字。

## 3. 方案取舍

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 前端聚合 | 前端用 `/api/factors` 分组计算 | 不选：规则只在前端，以后因子多了、命令行要用时得重写 |
| **B. 后端新增 `/api/bases`** | 后端拆解因子名、按原始因子聚合、算中位数和方向，有 pytest 覆盖 | **用户选定** |
| C. 只改造详情页 | 看板直接链到某个版本 | 不选：网址仍是版本，待中性化的因子没有合适入口 |

## 4. 规则（后端 `zer0factor/web/bases.py`）

- **拆解因子名**：与 `web/src/factorName.ts` 同一套规则：`[<z|rank>_[<size|industry|size_industry>_neu_]]<base>[_ma<N>]`，以及旧的 `z_neu_`。
- **主版本处理方式**：默认 `z_size_industry_neu`；市值类原始因子（`log_total_market_cap`、`log_circulating_market_cap`）用 `z_industry_neu`。写进配置 `[web.board]`（`primary_prep`、`industry_only_bases`），新因子只改配置。
- **主版本** = 该原始因子在主版本处理方式下的所有窗口（市值因子只有无窗口的一个）。数据取每个版本**最新一次标准评估**（沿用现有 `standard_rows`）。
- **方向**：主版本中已评估窗口的 `factor_direction` 全部一致时，显示“正向”（1，红）或“反向”（-1，绿），悬停说明“正向：因子值越大，未来收益越高”。不一致时显示“方向不一致”。
- **数字**：主版本已评估窗口方向调整 ICIR（`adjusted_ICIR`）的**中位数**。方向不一致时不给数字。悬停列出各窗口 ICIR，以及“已评估 k / n 个窗口”。
- **状态**：
  - `ok`：有数字。
  - `mixed`：方向不一致。
  - `unevaluated`（待评估）：主版本存在但一个都没评估。
  - `missing`（待中性化）：存储里没有主版本。
  - 后三种不显示数字，排序时放在最后，不拿别的版本顶替。

## 5. 接口

- `GET /api/bases`：每个原始因子一项：`base`、`primary_prep`、`status`、`direction`、`icir_median`、`windows: [{name, window, evaluated, icir, direction}]`（主版本各窗口）、`preps: [{prep, n_versions, n_evaluated}]`。
- `GET /api/bases/{base}`：该原始因子的全部版本：`[{name, prep, window, evaluated, icir, direction, run_id}]`，以及 `primary_prep` 和 `default_prep`。404 表示没有这个原始因子。
- 现有接口全部保留不变。

## 6. 前端

### 6.1 看板 `/`

- 列：**因子**（中文名 + 英文 base）、**方向**，以及原看板的全部指标列（方向调整 IC、ICIR、t 值、IC 胜率、多头年化、多头回撤、多头夏普、多头超额、单调性、多头换手、样本区间、评估 run），每个指标取主版本各窗口的中位数。默认按 ICIR 中位数降序。表格只列 `ok` 状态的原始因子；其余（待中性化 / 待评估 / 方向不一致）收在标题旁“另有 N 个待处理”的弹层里，可点进主页。（2026-11-08 用户确认。）保留“列设置”。（2026-11-08 用户追加：指标数量与原看板一致。）
- 保留搜索框和刷新。删除：矩阵视图（`FactorMatrix`）、“折叠成族”、热力着色、迷你曲线、处理方式 / 原始因子 / 窗口 / 方向 / 分类 / 标签筛选、行勾选框。
- 点击一行进入因子主页。看板上不放对比篮勾选。

### 6.2 因子主页 `/base/:base?prep=&win=&run=&period=`

- 顶部：中文名、base、方向标签。
- 第一排：处理方式标签页（原始 / Z / 市值中性 / 行业中性 / 行业+市值中性，以及存在时的 `z_neu`、Rank 系列；只显示存储里有的）。默认选主版本处理方式；没有主版本时，退回到已有处理方式中最靠后的那个（按“原始 → Z → 市值 → 行业 → 行业+市值”的顺序）。
- 第二排：周期按钮 MA5…MA180（含“无窗口”），每个按钮下小字显示 ICIR 或“未评估”（复用 `Siblings` 的样式，`Siblings` 组件本身删除）。默认选最短的已评估窗口；全部未评估时选最短窗口。**不默认选最好的窗口。** `h` / `l` 快捷键切换窗口。
- 下方：现有详情页内容原样复用（run 选择、持有期、核心指标、分组累计收益、分组收益、IC 分析、最新因子值）。
- 操作：“加入对比”加入的是当前版本；“重新评估”针对当前版本；新增“评估全部未评估窗口”，以标准口径打开新建评估抽屉，预填当前处理方式下所有未评估的窗口。
- 旧链接 `/factor/:name`：重定向到 `/base/<base>?prep=<prep>&win=<win>`，保留 `run` 和 `period`。对比页、因子族页里的因子链接都改成直接生成新链接。
